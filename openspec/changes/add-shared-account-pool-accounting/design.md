## Context

sub2api 已有账号管理、角色鉴权、用量日志、后台统计、CSV导出和 Vue 管理页面。`usage_logs.total_cost` 表示按模型标准定价计算的成本，`actual_cost` 受用户组倍率影响。本功能需要在不复制既有统计体系的前提下建立共享号池的资产与结算视图。

业务中存在三类身份：账号经济归属的贡献人、执行录入的上传人、实际使用代理的成员。三者可以是同一用户，也可以不同。采购成本还会因续费、涨价、退款、封禁和售后换号变化，因此单个可覆盖价格字段不足以形成可审计历史。

## Goals / Non-Goals

**Goals:**

- 准确记录账号身份、采购来源、付款、质保和生命周期。
- 支持日、周、月、自定义区间预览，并生成日期互斥的正式账单。
- 以模型标准计价统一不同模型与Token类型的用量权重。
- 以人民币分为结算事实值，保证明细合计严格等于本期池成本。
- 区分AA责任、采购垫付和资产回本，避免余额账本交叉记账。
- 让成员了解自己的账单，让维护员共同维护资产，同时保护账号凭据。

**Non-Goals:**

- 第一版只提供一个共享号池和一个结算币种 CNY。
- 结算结果用于人工转账确认，不联动用户余额。
- 第一版汇率由管理员录入并形成快照，不接入外部实时汇率服务。
- 第一版来源质量采用描述性统计，不实现机器学习预测。

## Decisions

### 1. 账号元数据、采购来源和成本流水分离

账号增加：

```text
provider_identity        上游邮箱、用户名或账号编号
contributor_user_id      账号经济归属人
created_by_user_id       实际上传人
purchase_source_id       标准化采购来源
cost_sharing_enabled     是否参与共享核算
pool_status              active, suspended, banned, replaced, retired
```

`provider_identity` 属于敏感元数据，列表默认掩码显示，详情按权限返回。采购来源使用独立记录保存名称、平台主页和备注，账号保存订单号、购买时间、质保截止日。来源删除采用停用状态，历史关联保持有效。

成本使用追加式 `account_cost_entries`：

```text
account_id, payer_user_id, type
original_amount, currency
amount_minor_cny, fx_rate, fx_rate_date
service_start, service_end
paid_at, order_reference, note
reverses_entry_id, created_by_user_id, created_at
```

`type` 为 purchase、renewal、topup、refund、compensation 或 adjustment。金额事实值使用人民币分；原币和汇率只用于审计展示。修改既有成本通过冲销加新流水完成。相同账号的周期性服务价格版本使用不重叠服务期；一次性调整通过独立类型进入指定账期。

### 2. 统一时间、服务期和动态账期语义

所有业务周期以 `Asia/Shanghai` 展示并转换为 UTC 持久化，统一使用左闭右开区间 `[start, end)`：

- 日：本地自然日。
- 周：周一 00:00 至下周一 00:00。
- 月：自然月首日 00:00 至次月首日 00:00。
- 自定义：管理员选择起止日期，结束日期在界面按“包含当日”展示，API归一为次日 00:00。

成本按服务期与结算期重叠的本地自然日数摊销：

```text
本期成本 = 服务期总金额 × 重叠日数 / 服务期总日数
```

内部使用高精度有理数计算，正式账单落库为整数分。一个成本流水跨多个账期时，前序账期按最大余数规则取整，服务期最后一个账期吸收累计尾差，所有账期分摊合计等于该流水人民币分值。成本上涨通过新服务期流水生效，历史账期保持原价。

### 3. AA使用全池标准模型价值作为权重

调度器决定请求落到哪个账号，成员通常不控制账号选择。AA责任按全池成员同期标准用量分配，而非按请求命中的采购账号分配：

```text
C  = 本期成本流水摊销 + 上期结转 + 本期调整
Wi = 成员 i 在账期内成功且已定价 usage_logs.total_cost 之和
Ai = C × Wi / ΣWi
Ki = 成员 i 在本期被纳入成本快照的垫付金额
Ni = Ai - Ki
```

`Ni > 0` 表示应付，`Ni < 0` 表示应收。权重计算只纳入共享号池成员、共享核算账号及成功落库的业务日志；测试探测、失败重试和零标准价格记录单独统计。正式结算前要求已定价覆盖率达到 99%，剩余记录由管理员完成模型价格补录或创建有审计备注的调整。

成员应承担金额使用最大余数法分配到分，使用用户ID作为同余数的稳定次排序键，从而满足：

```text
Σ成员应承担 = 本期池成本
Σ成员净额 = 0（把外部采购付款视为成员贡献后）
```

当 `ΣWi = 0` 时，本期成本进入下一期结转，系统生成零责任草稿。每笔结转保存来源账期和金额，后续只消费一次。

### 4. 草稿重算，锁定后保存完整快照

结算包含 `draft`、`locked`、`paid` 三态。草稿按实时日志和成本流水重算；锁定时在一个数据库事务中保存：

- 账期、时区、周期类型和公式版本。
- 纳入的使用日志最大ID/过滤条件及聚合结果。
- 每笔成本流水的摊销金额、结转和调整。
- 每个成员的权重、比例、应承担、贡献抵扣、净额。
- 模型价格覆盖率、汇率版本、操作者和时间。

已锁定账期只读取快照，后续成本变更、退款和补价进入新的结算或冲销流程。正式账期的日期区间保持互斥；动态页面仍可对任意区间生成只读预览，预览不占用账期。

### 5. 回本按物理账号独立核算，和AA账单分离

回本衡量采购资产产生的模型等价使用价值，使用实际命中账号的 `usage_logs.account_id` 归属：

```text
Va = Σ(账号 a 的 usage_logs.total_cost × 请求日期汇率快照)
Ca = 购买 + 续费 + 充值 + 调整 - 退款 - 赔付
回本率 = Va / Ca
净价值 = Va - Ca
待回本金额 = max(Ca - Va, 0)
```

回本时间是单账号按时间排序的成本、退款、换号转入/转出和模型价值事件累计余额首次由负转为非负的时刻；同时返回最近一次跨越和当前是否仍已回本。`Ca <= 0` 显示为“已冲销”，回本率显示为空值，避免无穷或负比例。

所有实际成功用量按实际命中账号计值，不因后续生命周期事件反向过滤。确认封禁保存UTC发生时间、固定原因码、来源和操作者；退款只冲减该账号成本，不覆盖生命周期状态。售后换号通过 `replacement_account_id` 连接新旧账号，转出、转入和补价分别进入各自账号流水，两个物理账号不合并回本。

预计回本日使用最近14个本地自然日平均日价值，零用量日进入分母：

```text
预计剩余天数 = 待回本金额 / 最近14个自然日平均价值
```

观察不足7个自然日、有效用量不足3日或平均值为0时显示“数据不足”；确认封禁、换号和报废账号停止预测。该预测仅用于趋势展示，不进入正式账单。

### 6. 来源质量统计使用固定口径并展示样本量

采购来源页面按每个物理账号的采购来源归类，展示：

- 采购资产数与可用资产数。
- 7/30/90天确认封禁率。
- 平均与中位存活天数。
- 退款/赔付率、平均回本天数、整体回本率和未回本损失。

封禁率分母只包含已达到对应观察窗口的账号；质保换号后的新账号按自己的来源和生命周期进入新样本。样本量少于5时显示“样本较少”并退出正式排名，页面仍展示原始数据。

### 7. V1复用现有管理员权限和用量成员

本场景是少量可信朋友共同维护，V1复用开源版本已有的多管理员权限，不给 users 增加平行角色字段。号池资产、成本、生命周期、汇率和账单接口统一挂在 `/api/v1/admin/pool`，最终锁定仍由管理员执行。AA成员不依赖手工开关：只要活跃用户在账期内对共享核算账号产生正的已计价用量，就自动进入该期分摊。

账号凭据继续由既有账号管理链路负责；号池API只读写业务身份、贡献人、上传人、来源、成本和生命周期，不接收或返回凭据。上游身份、订单号和采购链接只在管理员页面展示，并加入审计敏感字段清理。独立维护员角色、成员自助账单和分字段脱敏留给后续 change。

### 8. 页面和API复用现有模式

前端新增“共享号池”页面，使用已有表格、状态标签、日期输入、图表、对话框、权限守卫和i18n。页面包括：

- 账号资产：身份、贡献人、上传人、来源、质保、状态、成本与回本摘要。
- AA结算：周期切换、预览/锁定、池成本、覆盖率、成员责任/贡献/净额、成本明细、结转和付款状态。
- 回本分析：总成本、等价价值、回本率、已回本数、封禁损失、单账号精确明细和来源质量。

后端路由使用现有 `/api/v1/admin` 和认证用户分组，不新增独立鉴权框架。聚合查询以 `usage_logs(created_at, user_id, account_id)` 和成本/生命周期时间索引为基础；锁定后页面读取结算快照，避免重复扫描全量日志。

### 9. 与余额账本隔离

共享号池的成本、成员责任、应收应付和付款状态使用独立表。生成、锁定或标记AA账单时，用户余额、订阅、充值订单和既有 usage log 金额保持原值。未来如需自动收款，以另一个 change 定义显式的双账本过账和幂等键。

## Migration and Rollback

1. 创建新增表和索引，再以可空字段扩展 accounts；旧数据保持可读。
2. 部署后先开放管理员补录，所有账号默认不参与正式共享结算。
3. 为现有账号补录贡献人、来源、采购/续费流水、服务期和资产状态。
4. 使用历史 usage log 生成预览并核对价格覆盖率、成本合计和尾差。
5. 首个正式账单由管理员人工锁定；独立维护员能力在后续 change 评估。

回滚使用上一版本应用镜像。新增表和可空字段保留，使旧版本仍可运行；回滚期间暂停新的号池写入。恢复新版本后按幂等键继续使用已有成本流水和锁定快照。数据库删除安排在独立维护窗口，并以账单导出和数据库备份为前置条件。

## Risks and Mitigations

- **历史数据不完整**：正式结算页显示缺失贡献人、成本、来源和模型价格清单，覆盖率达标后进入锁定流程。
- **浮点尾差**：成本和账单使用整数分，高精度只用于中间比例计算，最终采用确定性最大余数法。
- **重复结算**：正式账期互斥、成本摊销快照和结转消费记录受数据库唯一约束保护。
- **封禁误判**：临时异常与确认封禁分开，只有确认事件影响封禁统计；恢复事件保留完整时间线。
- **凭据暴露**：复用加密与二次验证，所有列表、统计、审计和导出使用脱敏DTO。
- **查询压力**：预览按限定日期聚合，锁定后读取快照；统计查询不进入代理请求链路。
