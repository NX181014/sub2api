## ADDED Requirements

### Requirement: 系统必须记录共享账号的业务身份和维护身份
系统 SHALL 为参与共享核算的账号记录上游身份、经济贡献人、实际上传人、采购来源和共享状态。贡献人与上传人 MUST 分开保存，已有账号允许这些字段为空并在首次正式结算前完成补录。

#### Scenario: 管理员登记自己购买的账号
- **WHEN** 管理员登记账号并选择自己为贡献人
- **THEN** 系统 MUST 保存当前操作者为上传人
- **THEN** 系统 MUST 保存所选用户为贡献人并记录管理操作审计

#### Scenario: 管理员代朋友录入账号
- **WHEN** 管理员上传账号并选择另一位成员为贡献人
- **THEN** 贡献人 MUST 是所选成员
- **THEN** 上传人 MUST 是当前管理员

#### Scenario: 旧账号尚未补录
- **WHEN** 已有账号缺少贡献人、来源或成本服务期
- **THEN** 账号转发和调度 MUST 保持原行为
- **THEN** 正式结算预检 MUST 列出缺失项

### Requirement: 采购来源、订单和质保必须可追溯
系统 SHALL 使用标准化采购来源记录关联账号，并保存订单引用、购买时间、质保截止日和来源备注。来源停用后，历史账号和统计 MUST 继续显示该来源快照。

#### Scenario: 创建来源并关联账号
- **WHEN** 管理员录入一个新来源和采购账号
- **THEN** 系统 MUST 保存来源的规范名称并校验同名重复
- **THEN** 账号 MUST 关联来源ID并保存订单和质保信息

### Requirement: 成本必须使用追加式流水和服务期
系统 SHALL 以追加式成本流水记录购买、续费、充值、价格变更、退款、换号转移和调整。每条流水 MUST 保存付款人、人民币分值、付款时间和适用服务期；历史流水修改使用冲销关系和新流水表达。

#### Scenario: 账号价格上涨
- **WHEN** 管理员录入从新日期开始生效的续费价格
- **THEN** 系统 MUST 创建新成本流水并保留旧价格服务期
- **THEN** 两个正式账期 MUST 分别使用其重叠日期对应的价格

#### Scenario: 录入人民币采购
- **WHEN** 管理员录入采购或续费成本
- **THEN** 系统 MUST 将人民币金额转换为整数分保存
- **THEN** 后续估值汇率变化 MUST 保持成本和已锁定账单金额不变

#### Scenario: 更正已录入成本
- **WHEN** 管理员更正一笔历史成本
- **THEN** 系统 MUST 创建指向原流水的冲销记录和正确的新流水
- **THEN** 审计查询 MUST 展示完整关联链

### Requirement: 账号生命周期必须区分异常、封禁和售后结果
系统 SHALL 以追加事件记录确认封禁、恢复、退款、售后换号和报废。确认封禁事件 MUST 保存UTC发生时间、固定原因码、来源和操作者；换号事件 MUST 连接旧账号与替代账号。临时限流继续使用既有账号运行状态，不进入采购资产生命周期。

#### Scenario: 账号确认封禁
- **WHEN** 管理员确认账号已封禁，或上游返回强违规/明确停用信号，或OpenAI账号连续第3次返回确认型403
- **THEN** 账号 MUST 进入 banned 状态
- **THEN** 自动事件 MUST 使用 `source=automatic`、空操作者并对同一连续封禁幂等
- **THEN** 401、402、429、5xx、验证错误和前两次403 MUST NOT 创建封禁事件

#### Scenario: 质保换号
- **WHEN** 封禁账号通过售后获得替代账号
- **THEN** 系统 MUST 创建 replacement 关系并为旧账号记录转出、为新账号记录转入
- **THEN** 新旧物理账号 MUST 各自独立计算成本、价值、封禁损失和回本

### Requirement: 号池管理必须复用现有管理员权限
系统 SHALL 将号池资产、成本、生命周期、汇率和账单接口放在现有 admin 路由守卫后。号池API MUST NOT 接收或返回账号凭据，并 MUST 将上游身份、订单号和采购链接纳入审计敏感字段清理。

#### Scenario: 非管理员访问号池接口
- **WHEN** 非管理员请求任一 `/api/v1/admin/pool` 接口
- **THEN** 现有管理员守卫 MUST 拒绝请求
- **THEN** 账号、流水和结算事实 MUST 保持原值

#### Scenario: 管理员查看号池台账
- **WHEN** 管理员打开共享号池页面
- **THEN** 页面 MUST 展示业务身份、贡献人、上传人、来源和成本
- **THEN** 响应 MUST 不包含 access token、refresh token、cookie 或账号凭据

### Requirement: 共享号池资产必须保持现有转发和余额账本语义
系统 SHALL 把账号资产、成本和AA责任保存在独立业务表。号池字段、成本流水和结算操作 SHALL 只影响统计与管理视图；模型请求调度、用户余额、充值订单和订阅账本继续使用现有语义。

#### Scenario: 锁定共享账单
- **WHEN** 管理员锁定或标记一笔共享号池账单已支付
- **THEN** 用户余额、充值订单和订阅记录 MUST 保持原值
- **THEN** 现有 usage log 的 `total_cost` 与 `actual_cost` MUST 保持原值
