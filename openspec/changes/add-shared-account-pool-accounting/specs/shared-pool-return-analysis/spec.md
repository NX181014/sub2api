## ADDED Requirements

### Requirement: 系统必须按模型标准计价计算账号等价价值
系统 SHALL 使用账号实际承载的成功业务请求 `usage_logs.total_cost` 计算模型等价价值，并按请求本地日期对应的汇率快照换算为人民币分。统计 MUST 保存模型价格和汇率版本，使锁定结果可复算。

#### Scenario: 账号产生多模型用量
- **WHEN** 同一账号在统计期内承载多个已定价模型请求
- **THEN** 系统 MUST 汇总各日志 `total_cost` 并按对应日期汇率换算
- **THEN** 用户组倍率 MUST 不影响账号等价价值

#### Scenario: 请求缺少模型价格
- **WHEN** 业务日志 `total_cost` 为0且存在可计价用量
- **THEN** 系统 MUST 将其列入待定价数量和模型清单
- **THEN** 回本统计 MUST 显示价格覆盖率

### Requirement: 系统必须精确计算每个物理账号的回本
系统 SHALL 按 `account_id` 分别展示净成本、累计模型等价价值、回本率、当前盈亏、未回本损失、首次和最近回本时间及当前是否仍已回本。净成本等于该账号购买、续费、充值、换号转入、调整减退款与换号转出；回本时间按成本和值事件的时间顺序累计，取余额由负转为非负的精确时刻。

#### Scenario: 账号达到采购成本
- **WHEN** 账号净成本为10000分且累计模型价值首次达到10000分
- **THEN** 回本率 MUST 为100%
- **THEN** 首次回本时间 MUST 是累计余额首次由负转为非负的事件时间

#### Scenario: 净成本被全部冲销
- **WHEN** 退款和赔付使账号净成本小于或等于0
- **THEN** 状态 MUST 显示已冲销
- **THEN** 回本率 MUST 显示为空值并保留净价值金额

#### Scenario: 售后换号保持账号隔离
- **WHEN** 原账号封禁后换为新账号且存在实际补价
- **THEN** 原账号 MUST 记录换号转出且新账号 MUST 记录换号转入和实际补价
- **THEN** 新旧账号的模型价值和回本结果 MUST 分别归属各自 `account_id`

### Requirement: 封禁、恢复和退款必须影响回本生命周期
系统 SHALL 保留账号全部实际成功业务用量产生的模型价值，不因后续生命周期事件反向过滤。退款和赔付按事件对应成本流水冲减净成本，退款事件不覆盖账号的生命周期状态。

#### Scenario: 未回本账号被封禁
- **WHEN** 账号确认封禁时累计价值低于净成本
- **THEN** 系统 MUST 显示封禁时未回本损失、存活天数和质保剩余天数

#### Scenario: 封禁记录后仍有成功业务用量
- **WHEN** 账号在确认封禁后仍存在实际成功业务日志
- **THEN** 成功日志 MUST 继续按实际账号计入累计价值
- **THEN** 已记录的封禁时间和原因 MUST 保持可追溯

#### Scenario: 质保退款到账
- **WHEN** 管理员记录关联原成本的退款流水
- **THEN** 资产净成本 MUST 按退款人民币分值冲减
- **THEN** 原成本、退款和操作记录 MUST 同时保留

### Requirement: 预计回本必须使用可解释的近期速率
系统 SHALL 使用最近14个本地自然日的平均模型价值预测剩余回本天数，零用量日进入分母。观察期少于7个自然日、有效用量少于3天、平均值为0，或账号已确认封禁、换号、报废时，系统 SHALL 不返回预测；预测值只用于展示。

#### Scenario: 存在14个自然日观察窗口
- **WHEN** 账号待回本金额为14000分且最近14个自然日平均价值为1000分
- **THEN** 预计剩余时间 MUST 为14天
- **THEN** 页面 MUST 展示使用的窗口和平均日价值

#### Scenario: 新账号样本不足
- **WHEN** 账号只有2个有效使用日
- **THEN** 预计回本日 MUST 显示数据不足
- **THEN** 已发生的成本、价值和回本率 MUST 继续展示

### Requirement: 采购来源质量必须使用成熟样本口径
系统 SHALL 按每个物理账号的采购来源统计账号数、7/30/90天确认封禁率、平均存活天数、退款率、整体回本率和未回本损失。每项封禁率的分母 MUST 只包含达到对应观察窗口的账号。

#### Scenario: 计算30天封禁率
- **WHEN** 来源有10个账号，其中6个已观察满30天且2个在30天内确认封禁
- **THEN** 30天封禁率 MUST 为2/6
- **THEN** 页面 MUST 同时展示分子、分母和总样本数

#### Scenario: 来源样本较少
- **WHEN** 来源有效账号少于5个
- **THEN** 页面 MUST 显示样本较少
- **THEN** 该来源 MUST 退出正式排名但保留原始统计

#### Scenario: 质保换号
- **WHEN** 来源提供的账号在质保内封禁并换号
- **THEN** 来源封禁统计 MUST 记录一次确认封禁
- **THEN** 替换账号 MUST 按自己的采购来源、存活期、价值和成本作为独立样本

### Requirement: 回本页面必须提供截至日期的全生命周期视图
系统 SHALL 提供号池总览、单账号明细和来源质量三个视图。回本事实从采购日起累计到所选账期结束日；账期起始日只用于同期AA结算，不截断资产历史。

#### Scenario: 切换周期视图
- **WHEN** 管理员从月视图切换到自定义区间
- **THEN** 回本查询截止日 MUST 跟随新区间结束日
- **THEN** 每个账号的全生命周期净成本、累计价值和换号转入/转出 MUST 保持累计事实口径

#### Scenario: 管理员查看回本总览
- **WHEN** 管理员打开回本页面
- **THEN** 页面 MUST 展示池级聚合、单账号精确回本和来源统计
- **THEN** 页面 MUST 不读取或展示账号凭据
